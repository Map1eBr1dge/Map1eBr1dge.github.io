问题与方案

§ 01
系统盘满了,
真正麻烦的不是删一个大文件,
而是两个判断。

当 C 盘飘红,大多数人第一反应是找一个大文件删掉。但这往往治标不治本 — 真正要回答的是两个问题:

判断一　空间被谁占了?
判断二　哪些东西可以动?

BlueTidy 把这两件事拆开做。文件夹模式回答"空间去哪了",应用模式回答"软件能不能清理或迁移"。所有操作可回滚 — 你可以放心试,试错了退回来。

两个模式

§ 02

文件夹模式 FOLDER MODE

找空间去哪了,决定是否迁移数据目录。扫描任意卷或目录,用矩形图直观呈现占用分布。

  • 矩形图(Treemap)　按目录层级嵌套呈现占用比例
  • 占用排行　按体积排序,一眼锁定最大目录
  • CSV 导出　扫描结果可导出供外部分析
  • 快照对比　不同时间点快照,看空间变化趋势
  • 目录迁移　将数据目录迁移到其他卷并建链接
SCAN → ANALYZE → DECIDE → MIGRATE

应用模式 APP MODE

判断软件能否清理、迁移或回滚。从多个来源发现已安装的软件资产,给出每项的可操作建议。

  • 多来源发现　卸载注册表 / winget / Scoop / Steam / Epic
  • 占用归因　定位每个应用在磁盘上的实际体积
  • 可操作建议　清理 / 迁移 / 回滚 三种操作判定
  • 跨卷迁移　把大型应用搬到其他卷并保留可用性
  • 操作回滚　迁移失败或反悔时一键退回原状态
DISCOVER → ASSESS → ACT → ROLLBACK

安全边界

§ 03

BlueTidy 在执行任何操作前会跑一遍预检流程。下面每一项都是一道闸门 — 任何一道不通过,操作就不会执行。

01 / 06

阻止受保护路径

✓系统目录、Program Files、用户配置等受保护路径默认不可操作,防止误删关键文件。

02 / 06

检查目标卷空间

✓迁移前计算目标卷可用空间,不足则提前终止,避免写到一半磁盘爆满。

03 / 06

检测运行中进程

✓操作前检测目标目录或应用是否有进程占用,避免文件被锁导致损坏。

04 / 06

跨卷复制后核对

✓跨卷迁移采用"先复制再核对最后删除"三步法,核对通过才删除源文件。

05 / 06

单操作锁

✓同一时间只允许一个破坏性操作运行,防止并发写入造成状态不一致。

06 / 06

完整操作回滚

✓每个破坏性操作记录回滚信息,失败或手动撤销时恢复到操作前状态。

TidyPilot

§ 04

本地规则优先,
AI 只解释不绕过。

TidyPilot 是 BlueTidy 内置的辅助引擎。它先跑本地预检规则给出确定性判断,再可选调用 OpenAI 兼容接口生成自然语言解释 — 告诉你"为什么建议这样做"。

AI 永远不能绕过本地预检。它只负责把工程判断翻译成人话,不负责做决定。

RULE PRIORITY
LOCAL 受保护路径拦截 — 硬性阻断,不可覆盖
LOCAL 目标卷空间核算 — 不足即终止
LOCAL 进程占用检测 — 锁定文件不可动
AI 生成操作解释与建议文案(只读)
AI 回答用户关于扫描结果的提问

运行要求 · REQUIREMENTS

  • Windows 10 1809+ 或 Windows 11
  • 64 位系统(x64 架构)
  • Edge WebView2 Runtime(系统通常已内置)
  • 至少 200 MB 可用磁盘空间
  • 管理员权限(迁移系统目录时需要)
  • 可选:OpenAI 兼容 API Key(用于 TidyPilot)
