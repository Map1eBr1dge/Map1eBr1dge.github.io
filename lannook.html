它解决什么

§ 01

文件就在手机或身边电脑上,只想直接送到另一台设备。

常见的传文件方式要么依赖云盘中转、要么要求双方安装同一个 App、要么需要注册账号。如果只是把一张截图从手机挪到电脑、把一个安装包从电脑发到手机,这些前置成本显得过重。

LanNook 的做法很直接:电脑运行程序后,在局域网内提供一个二维码和地址;手机用自带浏览器打开,就能双向选择文件和目标设备。官方发行版不会把文件上传到公共云盘,数据只在你自己的局域网里流动。

前提:电脑和手机需连接同一个局域网(同一路由器 / 同一 Wi-Fi)。

对比 · COMPARISON
✕
云盘中转 文件先上传到公共服务器,再从另一端下载。需要账号,依赖外网带宽。
✕
社交 App 互发 双方都要装同一个 App、加好友,文件还可能被压缩。
✕
数据线 需要线缆、驱动、授权弹窗,跨平台体验割裂。
✓
LanNook 电脑开程序,手机扫码,浏览器里直接传。不装 App、不注册、不上云。

第一次使用

§ 02
01

电脑启动 LanNook

打开桌面端程序,主界面确认状态为 运行中。此时程序已在局域网内监听服务,等待设备接入。

STEP · BOOT
02

点击"连接设备"

在电脑端点击 连接设备,界面会展示二维码和局域网地址。手机用自带浏览器扫描二维码,或手动在地址栏输入地址即可打开传输页面。

STEP · PAIR
03

审批接入请求

新设备默认会弹出接入请求。你可以选择 仅本次允许 或 信任此设备。被信任的设备下次接入时不再重复询问。

STEP · APPROVE
04

选文件并查看进度

在手机或电脑上选择文件和目标设备,发起传输。到 传输中心 查看进行中与已完成的任务进度,支持多文件并行。

STEP · TRANSFER

§ 03

浏览器端运行

手机无需安装任何 App,用系统自带浏览器打开页面即可使用全部传输功能。

// no app required

双向传文件

手机到电脑、电脑到手机,两个方向都可以发起传输,自由选择目标设备。

// bidirectional

传输中心

集中查看所有进行中与已完成的传输任务,掌握进度与状态,支持多文件并行。

// transfer hub

512KiB 分块上传

大文件按 512KiB 分块上传,单块失败自动重试,提升弱网环境下的传输可靠性。

// 512KiB chunks

SHA-256 指纹

传输完成后对文件计算 SHA-256 指纹校验,确保送达的文件与源文件逐字节一致。

// sha-256 verify

SQLite 本地存储

设备信任记录、传输历史等数据存储在本地 SQLite 数据库,不上传任何外部服务器。

// sqlite local

mDNS 发现

通过 mDNS 在局域网内自动发现运行 LanNook 的设备,减少手动输入地址的步骤。

// mdns discovery

系统托盘

程序最小化到系统托盘常驻后台,关闭窗口不退出服务,随时等待设备接入。

// system tray

开机自启

支持设置开机自动启动,开机即就绪,无需每次手动打开程序。

// autostart

签名更新

程序内置更新检查,新版本通过签名校验后自动推送,保证更新包来源可信。

// signed update

安全边界

§ 05

新设备默认需审批

任何新设备首次接入时,电脑端默认弹出审批请求。可选择 仅本次允许 或 信任此设备,被信任的设备后续不再询问。

二维码含配对参数

二维码内嵌的地址携带配对参数,扫码即建立关联会话,降低手动输入地址时被旁人窥探的风险。

局域网明文传输

HTTP 与 WebSocket 均为明文通信,未使用 TLS。这是局域网点对点传输的取舍 — 不引入证书管理复杂度,但请确保只在可信网络中使用。

默认不上传公共云

官方发行版的设计原则是数据不离开局域网。文件在设备间直接传输,不经由任何公共云服务器中转或存储。
